# Strictly lagged NFL team-form candidate (not adopted)

This lean rebuild is **not** the old v3.2b model and must not be described as its repaired performance. The 15 selected features use only completed prior games: 2023 validation was held out from 2010-22 training, followed by the locked 2024-25 test. Team game statistics come from the public nflverse weekly player-stats release; scores and schedule come from the public nflverse games release. Inputs are restored with checksums in `../repro/source_manifest.json` and `../repro/restore_inputs.py`. The book's closing spread and moneyline are evaluation benchmarks only, never inputs.

`build_frame.py` derives prior-season team point/yard averages from the *previous completed season* and shifted within-season rolling stats; no current-season final mean fallback, future game outcomes, target-game QB identity, full-season roster participation, same-game snaps or final weather values enter a feature. Teams without prior-season coverage, notably early 2010, remain missing and are excluded, not filled from future data. `test_chronology.py` poisons target-game statistics, truncates later seasons, and poisons Week 1, checking that the scored row is unchanged. A separate date-only as-of cutoff masks results on and after that date even if a revised upstream games file contains them; scheduled unplayed games neither increment games played nor displace the last-four completed games. The as-of tests poison same-date and future scores and remove unplayed schedule rows to check these properties. The [nflverse update schedule](https://nflreadr.nflverse.com/articles/nflverse_data_schedule.html) says weekly player/team stats update nightly after each game day, with additional in-day updates, and the game schedule updates every five minutes. This supports completed prior-game availability for the usual following-week run but does not establish historical publication timestamps for every prior game used here. The restored files are retrospective snapshots, not as-of archives. A game-by-game publication-timing audit remains necessary before a fully strict point-in-time claim. In particular, date-only as-of cannot resolve same-day postgame availability: it conservatively excludes all same-date games.

`python3 tools/model_nfl_v3_2/point_in_time/build_frame.py --out /tmp/nfl-pit-2010-25.parquet` builds the frame using the restored files in `/tmp/training/nflv32`. `python3 tools/model_nfl_v3_2/point_in_time/test_chronology.py` checks the chronology invariants. `python3 tools/model_nfl_v3_2/point_in_time/evaluate.py /tmp/nfl-pit-2010-25.parquet` runs the predeclared fixed-feature Ridge (alpha 10) and straight-up logistic calibration using prior-season rolling folds. The frame is a recoverable build product, not an adopted artifact; its source manifest and evaluation hash are saved.

The first candidate fails clean validation and the locked-test market gate: validation MAE 10.742 versus closing spread 9.818; locked-test MAE 10.414 versus 9.804, 95% bootstrap model-minus-market CI [+0.293,+0.911]; winner accuracy 62.5% versus closing spread direction 67.6%; Brier 0.2204 versus closing moneyline 0.2075. No Week 4 NFL model number, pick or probability is published. This form-only model is not injury/QB/weather adjusted; dated 2026 player-status and weather inputs and an as-of scoring artifact are still outstanding. A Saturday deadline is not a reason to override this gate.

As-of freshness check (Sep 29): a newly released [nflverse 2026 weekly player-stat file](https://github.com/nflverse/nflverse-data/releases/download/stats_player/stats_player_week_2026.csv), SHA256 `c7a28afdad525e2bd0a4fde36c4cfc1b069cea9f56617336fe0252b38cf93262`, contains 16 Week 3 games; the repo's older Week 2 copy must not be used for Week 4. With `--as-of 2026-09-29`, the builder rejects missing completed-game team stats and yields all 16 Week 4 rows with finite lagged form. This is an input-completeness check, not permission to score or publish a failed model. On rerun after hardening, all 16 Week 4 rows remain finite and have null target margins; historical validation and locked-test metrics are unchanged. The 2026 stat file is scratch input with its SHA recorded here, not a historical as-of archive. Historical NFL team aliases OAK/SD/STL are normalized solely for this check because nflverse player stats use LV/LAC/LA.
